# D1 stage environment recovery — 1846 / 1847

## Classification

Technical-only execution failure. No D1 scientific verdict was produced by either attempt.

## Affected attempts

- `cpx62-1846-l3-decision-math-d1-wdl-listwise-fit-v1`
  - attempt `20260906T204702Z-2da8293b`
- `cpx62-1847-l3-decision-math-d1-wdl-listwise-fit-historical-split-recovery-v1`
  - attempt `20260906T211833Z-91414e25`

Both attempts reached stage-runner `EXECUTE`, exited 1 after about five minutes, authenticated their stage inputs, authenticated no D1 outputs, and produced no scientific verdict.

## Primary root cause

`jobs/tools/run_experiment_stage.py` intentionally constructs a sanitized stage environment. Among runner-owned `JASS_*` provenance variables it preserves only `JASS_JOB_ID` and `JASS_ATTEMPT_ID`, plus the code/result/artifact/spec paths it creates itself. Arbitrary outer variables such as `EXPECTED_CODE_SHA` are not propagated into the scientific stage.

The D1 v1/v2 templates nevertheless began with:

```bash
: "${EXPECTED_CODE_SHA:?}"
```

before installing their `EXIT`/`ERR` traps. Therefore the shell exited immediately when the sanitized stage began. This exactly explains why neither failed attempt published the template-owned `RESULTS.txt` or `logs.tar.gz`: the template terminated before creating them.

## Secondary latent issue discovered during recovery

The first recovery also corrected a separate historical split cardinality assumption. CURRENT_2M is split by complete opening/game groups using seed `577215` and `holdout-mod=10`; its immutable counts are:

- records: `2,000,000`
- train: `1,800,796`
- holdout: `199,204`

The earlier D1 implementation had confused the separately preregistered `200,000` bootstrap replications with a hypothetical `200,000` holdout row count. That bug was real but was not the primary cause of the immediate 1846/1847 stage exits.

## Repair

A v3 D1 stage entrypoint reconstructs `EXPECTED_CODE_SHA` exclusively from the already-authenticated `JASS_STAGE_SPEC`, verifies that it equals repository HEAD, exports it inside the stage, and then execs the unchanged v2 historical-split D1 template.

The new regression test launches this entrypoint with a deliberately sanitized environment containing no `EXPECTED_CODE_SHA`. It proves:

1. the SHA is reconstructed from the stage spec and passed to the base template;
2. a spec/HEAD mismatch fails closed;
3. the v2 historical split remains `1,800,796 / 199,204`.
