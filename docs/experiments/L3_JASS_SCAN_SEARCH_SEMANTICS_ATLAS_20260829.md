## 2. Executive map

Both engines use iterative-deepening negamax/alpha-beta, PVS, a clustered transposition table, mandatory-capture quiescence, mate-distance scores, and side-to-move score propagation. They do **not** instantiate the same search graph at a nominally equal node budget. The largest source-level families of difference are:

1. Scan's same-position verification probe versus Jass's independent collection of RFP, null move, razoring, ProbCut, multi-cut, LMP and singular search;
2. Scan's exact quiet-threat qsearch re-entry versus Jass's default in-qsearch emulation;
3. Scan's unconditional single-reply extension versus the production-off Jass implementation;
4. Scan's fixed LMR eligibility/reduction versus Jass's depth/index/improving-shaped LMR;
5. Scan's reset-per-search probabilistic from/to ordering, including captures and good/bad updates, versus Jass's production cutoff-based ordering machinery;
6. materially different root/PVS/aspiration, draw, tablebase, node-count and maximum-ply contracts.

This is a map of mechanisms only. No item above is claimed to explain an observed accuracy gap until a preregistered causal contrast passes.

## 4. Frozen source-derived axes for Attribution V1

The cap is six. Selection uses only the atlas above, with this mechanical priority:

1. first select minimal mechanisms explicitly present in frozen Scan but absent or non-identical in production Jass, provided every constant/condition has a direct source correspondence;
2. then select structurally distinct Jass-only semantics whose removal is binary and needs no imported/tuned value;
3. reject any candidate requiring a score-scale conversion, arbitrary recursion/depth cap, margin choice, or compound root rewrite.

The resulting frozen axes, in mechanical application order, are:

| Axis ID | Hypothesis (mechanical, not a result claim) | Minimal treatment relative to J0 | Exact source basis |
|---|---|---|---|
| `A1_SCAN_VERIFY` | Scan's same-position verification probe may allocate finite nodes differently from production selective pruning. | Enable the existing exact frozen verification path only; keep every Jass production pruner active. | Scan `src/search.cpp:1137-1160`; Jass `src/search.cpp:930-956`. Constants are fixed: depth >=3, `10*depth`, 40% depth, non-PV, eval score band, no recursive verify. |
| `A2_SCAN_THREAT_REENTRY` | The same-board main-search re-entry may resolve threatened quiet horizons differently from Jass's reply-enumerating qsearch emulation. | Disable `qs_threat_ext`; enable `scan_threat_reentry`; no other qsearch change. | Scan `src/search.cpp:1332-1336`; Jass `src/search.cpp:651-687`. |
| `A3_SCAN_SINGLE_REPLY` | Extending a width-one node may preserve forced sequences at negligible branching cost. | Enable the existing single-reply extension only. | Scan `src/search.cpp:1405-1423`; Jass `src/search.cpp:1369-1387`. |
| `A4_SCAN_LMR` | Scan's fixed late-move eligibility/reduction may retain or discard different quiet lines than Jass's shaped LMR. | Dedicated exact-Scan LMR switch: depth >=2; PV move index >=3, non-PV >=1; no captures/promotions; reduction 2 only for non-PV index >=4 else 1; extension cancels reduction; Scan-style single re-search. ## 5. Source-derived candidates deliberately not tested in V1

- Scan aspiration: rejected because a 10-unit Scan window has no unique CURRICULUM-scale counterpart.
- recursive selective sacrifices: rejected because Scan has no explicit recursion count and Jass's available count 8 is not source-derived.
- full TT replacement/probe-order port: rejected as a non-minimal storage and score-band redesign.
- root/PV scheduling replacement: rejected as compound with aspiration and interruption reporting.
- LMP, RFP, razoring, ProbCut and multi-cut removals: each is a real source difference, but omitted by the six-axis cap after the five exact Scan mechanisms and the structurally distinct null-move absence were selected.
- draw/TB/MAX_PLY changes: held as disclosed engine-contract differences, not treated as isolated heuristic arms.

## 6. Technical consequences for the preregistration

- Primary comparisons must be at an exact requested node cap, while explicitly acknowledging that Jass and Scan count different search objects.
- Every Jass sibling/arm gets a fresh Engine, TT and search state; otherwise ordering and TT differences become asymmetric.
- Passive receipts must include nodes, completed/effective depth, wall time/NPS, eval calls, qsearch entries/nodes, TT probes/hits, cutoffs, reductions/reduced plies, extensions, and per-axis event counters.
- Static evaluator bytes, legal children, terminal/TB metadata, thread count, book setting, TT size and exact-node mode must be identical across `J0` and every `Ji`.
- The source atlas provides hypotheses only. Holm-corrected fresh-cohort results decide establishment.
