# L3 — Frozen R2 archive mining for exact TB-frontier sibling decisions

Date: 2026-08-25. Status: **preregistered before archive mining and before any archive-derived pairwise fit**.

## Motivation

Fresh NORMAL CURRICULUM Phase A (job 1564) generated exactly 4,000,000 JNNW rows but found only 171 unique informative 8-piece parents, with 31 parents in the frozen 1/5 holdout. The preregistered support gate required at least 800 holdout parents and at least 250 per colour, so the correct terminal verdict was `TB_FRONTIER_SUPPORT_NOT_ESTABLISHED`. This was a support failure, not a negative ranking result: no new policy model was fit.

The next experiment changes **acquisition only**. It reuses the already completed MegaCorpus R2 census instead of generating more self-play. No source score, source WDL, teacher label, replay weight or prior strength result is trusted. Every retained sibling preference is reconstructed anew from exact EGDB WLD.

## Two acquisition layers fixed before reading support

### Layer 1 — direct R2 payloads

The first mining job processes every catalog candidate satisfying all of:

1. `data.r2_uri` is non-null;
2. path ends in `.jnnw` or `.jnnw.gz`;
3. census disposition is not `reject`.

Candidates are sorted deterministically by `(data.path, candidate_id)`. Byte-identical candidate payloads are de-duplicated before download by `declared_sha256` when present, otherwise by URI.

The old MegaCorpus risk tags (`external_or_teacher`, `specialist_or_filtered`, `derived_mix`, `split_or_holdout`) are **not exclusion criteria** for this experiment. They described whether historical labels could safely enter a scalar training corpus. Here the source target bytes are ignored completely; the corpus contributes only a board position and side to move. Exact sibling labels are regenerated by EGDB. Global parent-fingerprint de-duplication prevents derived copies from inflating statistical support.

Malformed, unsupported legacy file formats are reported as unsupported and contribute zero parents. Failure to retrieve an object that the frozen census says exists is a technical failure, not a scientific exclusion.

### Layer 2 — historical Git snapshots

The 986 census candidates with `data.r2_uri == null` are a **predefined second layer**, not a post-hoc rescue cohort. They require restoration from their census `archive_locator`. Layer 2 is run only if Layer 1 fails the support gate. It uses the same extractor, exact-label rule, global parent de-duplication and frozen split. No learner threshold may change between layers.

## Exact decision label

The real CPX62 EGDB is frozen at `max_pieces = 7`; therefore candidate parents have exactly 8 pieces.

For every source JNNW row, the extractor uses only:

- white men bitboard;
- white kings bitboard;
- black men bitboard;
- black kings bitboard;
- side to move.

The source score and WDL bytes are ignored.

A parent is retained iff:

1. it has exactly 8 pieces;
2. at least two distinct semantic legal moves exist and the legal moves are captures;
3. **every** legal sibling child has at most 7 pieces and an exact EGDB WLD result;
4. at least two sibling moves have different exact WLD utilities from the parent side-to-move point of view.

MTC is not used. No shallow/deep search score participates in the target.

Across all sources, an exact parent fingerprint `(wm,wk,bm,bk,stm)` may contribute at most once. The first occurrence in deterministic catalog order supplies provenance; later occurrences are counted as duplicates only.

## Frozen split and support gate

The parent-disjoint split remains byte-for-byte the Phase-A rule:

```text
holdout = little_endian_u64(SHA256("2026082801:" + parent_fingerprint)[0:8]) % 5 == 0
```

Support is established only if, after global parent de-duplication:

- holdout parents >= **800**;
- white-to-move holdout parents >= **250**;
- black-to-move holdout parents >= **250**;
- both training colour banks are non-empty.

The Layer-1 terminal markers are:

- `TB_FRONTIER_ARCHIVE_SUPPORT_ESTABLISHED`
- `TB_FRONTIER_ARCHIVE_SUPPORT_NOT_ESTABLISHED`

Layer 1 performs **zero pairwise fits, zero PatternEval fits, zero strength games, zero frozen reads and zero promotion**. If Layer 1 passes, a separate preregistered job may run the unchanged 126-feature learner. If Layer 1 fails, only the already-defined historical-snapshot Layer 2 is authorized.

## Downstream learner if and only if support passes

No learner parameter is changed from the original TB-frontier preregistration:

- features: exact 120 production eval extras + 6 move-local features;
- separate white/black banks;
- pairwise logistic objective on exact WLD sibling preferences;
- `l2 = 1e-3`;
- `maxiter = 500`;
- `gtol = 1e-6`;
- maximum 250,000 training pairs per colour;
- bootstrap 100,000, seed `2026082802`;
- 16 label shams, seed `2026082803`;
- minimum model pairwise accuracy 0.58;
- original bootstrap/top-hit/both-colours/sham gates remain unchanged.

CURRICULUM remains frozen as the baseline and, even after a positive learner result, remains the only leaf evaluator until a separately preregistered move-ordering strength experiment.

## Interpretation

A support PASS means only that historical data contain enough independently split exact decisions to test D rigorously. It is not evidence that the learned policy beats CURRICULUM. A support FAIL means passive historical self-play also undersamples this exact frontier and motivates direct legal-state acquisition rather than ever larger generic self-play volumes.
